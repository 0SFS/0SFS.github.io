This is the sharper form of the stage's central claim. Each of the three new
fuel tests fails individually on the published #1508 head **and** on the
spool-only control, and passes on the candidate, while all three pre-existing
running tests pass on all three sources. So the fuel guard is what the new
tests are sensitive to, and it changes nothing the existing running tests
measure.

It also confirms the report's account of the control's two spool failures.
Stage 0's `assert_stays_off` asserts an off engine's fuel flow as well as its
spools, so on the control it fails on the flow, not on a spool:

```
File "tests/TestTurbineTrimSpool.py", line 110, in assert_stays_off
  self.assertEqual(fdm[ENGINE + "fuel-flow-rate-pps"], 0.0)
AssertionError: 13.323485924466473 != 0.0
```

That is #1508's regression caught by stage 0's own test, and it is why the
stage-0 spool proof could not simply be carried over to this stack unchanged:
on the stacked control that test file fails until the fuel guard lands.
`test_zero_time_trim_updates_both_spools` passes everywhere, so the running
spool behaviour #1505 exists to establish is intact in all three sources.
